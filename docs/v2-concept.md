# Personal Dashboard V2 — концепция продукта

## Зачем он нужен

Personal Dashboard V2 — личное пространство для знаний, планов и текущей работы. Его цель — помочь складывать разрозненные заметки в понятную структуру, видеть движение по проектам и спокойно выполнять задачи дня. По мере накопления данных приложение должно помогать находить связи и наводить порядок, а не превращаться в ещё один список, который трудно обозреть.

**Основной способ работы — ручной.** Пользователь сам создаёт и редактирует документы, планы и задачи в удобных специализированных разделах. Поиск и чат дают второй способ работать с теми же данными: найти нужное по смыслу, обсудить, проанализировать и, после подтверждения, изменить.

V2 разрабатывается с нуля. Текущая версия служит примером полезных сценариев, включая предпросмотр действий агента; её код не переносится. Кликабельный [макет](../v2/mockup/README.md) — ориентир для интерфейса. Его навигация, экраны и жесты уже подробно проработаны; дальнейшие изменения UX вносятся по результатам использования, а не ради смены стека.

## Три рабочих раздела

### База знаний — собрать и осмыслить

Единое дерево разделов и Markdown-документов для заметок, идей, решений, исследований и сведений о любых проектах или личных темах. Пользователь может создать документ в нужном месте, открыть его, изменить заголовок и содержание, переместить, переупорядочить или найти. Структура помогает видеть, что уже известно и где лежит материал; поиск и чат помогают обнаружить связи, которые не отражены в дереве.

### Планирование — видеть перспективу

План строится как `проект → веха → фича → задача`. Проект показывает направление, вехи — крупные этапы, фичи — результаты внутри этапа, задачи — конкретные действия. Прогресс проекта и вехи определяется **состоянием фич**, а не числом закрытых задач: задачи могут добавляться, меняться и отменяться. Завершённость фичи отмечается явно.

Задачу из плана можно отправить в рабочий Backlog и при необходимости вернуть обратно без создания копии и потери связи с проектом и фичей. Планирование должно помогать понять, что уже сделано, что осталось и как движется проект. Прогноз дат — желаемое развитие: для достоверного прогноза потребуются оценки и фактический темп, одного процента готовности недостаточно.

### Задачи — действовать сегодня

Task Tracker — тактический раздел: Backlog хранит рабочую очередь, «Сегодня» — выбранные на день дела. Пользователь группирует задачи по разделам, меняет порядок, открывает описание, переносит задачи между Backlog и «Сегодня» и отмечает состояние «новая → в работе → готово». Задачи могут быть связаны с планом или существовать сами по себе. Здесь важна быстрая ручная работа без необходимости каждый раз обращаться к агенту.

## Единый поиск

Поиск доступен пользователю напрямую и агенту через инструмент. Он должен находить точные слова, части слов и совпадения по смыслу во всех трёх разделах. Например, вопрос про «декор города» должен приводить и к заметкам об «оформлении улиц», фонарях и растениях. Результат ведёт к исходному документу, фиче или задаче.

Для запроса «где я писал **всё** про декор?» важна полнота, а не только несколько наиболее похожих фрагментов. Известный пример с двумя документами, содержащими упоминания декора, станет проверкой качества: оба источника должны быть найдены и отражены в ответе. Поиск помогает получить материал; осмыслять, сопоставлять и объяснять его будет агент.

История чата тоже доступна для поиска по словам и смыслу. Вопрос «Что мы раньше решили по этому документу?» должен находить прежнее обсуждение, даже если оно было сформулировано иначе. Старые реплики показывают ход мысли и принятые решения; актуальное состояние документа, плана или задачи проверяется отдельно.

## Чат и агент

Один простой чат доступен из любого раздела. С ним можно разговаривать на любые темы, как с обычной LLM. Когда вопрос касается данных приложения, агент может искать и читать документы, планы и задачи, сопоставлять сведения между разделами, суммировать, выявлять противоречия и отвечать со ссылками на источники. Ему доступны также точные запросы к структуре данных: число задач или состояние проекта нельзя надёжно вычислять по нескольким найденным отрывкам.

Если чат открыт из документа или задачи, сверху по умолчанию выбран режим «Этот документ» или «Эта задача»: агент автоматически получает открытый объект и понимает обращения «здесь», «этот текст». Переключатель «Общий чат» убирает этот автоматический фокус; в нём можно говорить на любые темы и обращаться ко всему приложению. Режим определяет фокус, а не запрет на поиск: явная просьба найти связанные данные выполняется и из контекста документа. История остаётся единой; сообщения сохраняют отметку о режиме и объекте, к которому относился разговор.

В режиме открытого объекта можно попросить агента привести надиктованный текст в порядок, сократить без потери фактов, структурировать, изменить заголовок или выполнить другую разрешённую операцию с этим объектом. Результат показывается в чате как предложение с исходными и новыми значениями; кнопка подтверждения применяет только показанный вариант.

Главная цель такого чата — дать возможность **разобраться в собственных данных в диалоге**. Например: найти все заметки о декоре, сопоставить их с фичами и задачами, объяснить, что уже решено и что ещё открыто, а затем предложить, как упорядочить разрозненные записи. Агент должен видеть доступные ему данные через инструменты приложения, без ручного прикрепления полного JSON к каждому сообщению.

Агент может быть и помощником по редактированию. Пользователь описывает намерение обычными словами; агент определяет конкретные объекты и готовит создание, правку, перенос, архивирование или удаление. Если цель неоднозначна, он уточняет её. Поиск и ответы не требуют подтверждения. Изменяющие действия выполняются только после него:

1. Агент показывает понятный предпросмотр: какой объект затронут и что именно изменится.
2. Если действий несколько, каждое показывается **отдельным сообщением**; область действия кнопки подтверждения должна быть очевидной.
3. Пользователь может уточнить или исправить предложение. Переход к другой теме или уход из чата не выполняет ожидавшиеся действия.
4. Нажатие «Да, подтверждаю» разрешает выполнить только показанные действия. При изменении исходных данных после предпросмотра агент сообщает об этом и просит подтвердить обновлённый вариант.

## Локальная модель и работа без сети

Основная модель чата — локальная Gemma 4. Текстовый и смысловой поиск заранее отбирает релевантные материалы, чтобы модель читала их вместо всего хранилища. Это должно улучшить качество ответов на вопросы по данным приложения; результат нужно проверять на реальных запросах. Если запрос не удаётся корректно обработать, система может использовать более сильную модель, например DeepSeek. Выбор fallback не должен зависеть только от признания самой модели, что она не справилась.

В шапке чата на любом экране пользователь может вручную переключить модель: по умолчанию выбрана Gemma, альтернативный выбор — DeepSeek. Ручной выбор доступен независимо от автоматического fallback; основной сценарий рассчитан на работу с Gemma.

Приложение задумано как PWA: уже полученные данные доступны на устройстве без интернета, ручные изменения сохраняются локально и синхронизируются позже. Чат с AI работает, когда доступен его провайдер; отсутствие AI не мешает пользоваться тремя ручными разделами.

## Границы V2

Память агентов из старого интерфейса в V2 не входит. История обычных диалогов — часть Chat и не равна памяти внешних агентов. Автоматическая передача специально помеченных задач внешним агентам и их субагентам — возможное направление V3; в V2 задачи берёт в работу пользователь.
